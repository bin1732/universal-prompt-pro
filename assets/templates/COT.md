# Template: COT（Chain-of-Thought 思维链）

> 用途：数学/逻辑/调试/多步推理。选型信号：需要推理链路、问题可拆解。
> ⚠️ **o1/o3 等推理模型禁用 CoT 指令**（模型自带内部推理，显式 CoT 反而干扰——见 techniques.md 禁用清单）。
> 对应任务轴 A：数学/逻辑/调试。兜底：CO-STAR。

## 骨架

```
你是一个{推理角色}。

请按以下步骤逐步推理，并在每一步说明依据：
1. 理解问题：{用自己的话重述问题，确认理解无误}
2. 拆解：{把问题分解为可独立求解的子问题}
3. 求解：{逐步求解，每步标注依据}
4. 验证：{检查结果是否合理，是否有遗漏边界}

最后给出结论（单独成段，便于解析）：
结论：{最终答案}
```

## 使用要点
- 只用于推理任务；**o 系模型禁用**（techniques.md 硬规则）。
- "思考后再回答"+ 结论单独成段——结论独立便于程序解析（Verifiability 维）。
- 步骤数 2-6，不要为拆而拆（Economy 维：过长 CoT 烧 token）。
- 数学题要求"检验"步骤（防止自我确认偏误）。

## 反例（不该用 COT）
- 格式固定任务 → FEWSHOT
- 简单事实问答 → RTF
- o1/o3/o4 系列 → 禁用（模型自带推理）

## 环境适配
- DeepSeek：CoT 友好，可加"逐步推理"指令
- Claude/GPT(非 o 系)：标准 CoT 指令有效
- 国产小模型：CoT 收益明显，但注意输出长度预算
