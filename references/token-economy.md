# references/token-economy.md — Token 预算模型与压缩规则

> 用途：Economy 维评分 + compress 意图。**P3 已落地：scripts/token-count.mjs 实现估算/预算偏差/冗余检测（确定性 + 证据引用）。**

## 1. Token 估算口径（与 validate.mjs 一致）

| 内容 | 估算 | 说明 |
|------|------|------|
| 中文（含标点） | 1 字 ≈ 1.0 token | `[\u4e00-\u9fff\u3000-\u303f\uff00-\uffef]` |
| 英文单词 | 1 词 ≈ 1.3 token | 非中文字符分词计数 |

> 注：这是**估算**不是模型精确分词；用于预算偏差判断足够，精确值以目标模型 API 计费口径为准（诚实边界 P8）。

## 2. 预算档位自动判定规则（由 token-count.mjs `budgetReport` 实现）

`偏差率 = (实际估算 - 目标预算) / 目标预算 × 100%`

| 档位 | 判定 | 处理建议 |
|------|------|----------|
| 精简档 | 偏差 ≤ -20% | 可用；如用户要更短可再压 |
| 标准档 | -20% < 偏差 ≤ 0 | 默认合理 |
| 超预算 | 0 < 偏差 ≤ 30% | 需压缩（优先删冗余，见 §3） |
| 严重超预算 | 偏差 > 30% | 必须压缩（删冗余 + 精简指令） |

**目标预算来源**：用户指定（`--budget <n>`）→ 环境指纹 context_budget → 模型窗口 2%（未指定时按任务复杂度估算）。

## 3. 冗余模式清单（token-count.mjs 检测规则，全部高置信防误伤）

| 类别 | 模式 | 示例 | 可省 |
|------|------|------|------|
| 同义堆叠 | 务必/一定/千万/切记连用 | "请务必一定千万要" | ~8 字符 |
| 同义堆叠 | 非常非常/十分特别 | "非常非常重要" | ~2 字符 |
| 无信息量套话 | 请充分发挥您的专业能力 | "充分发挥您的专业能力" | ~10 字符 |
| 无信息量套话 | 让我们一起努力/携手共进 | "让我们一起努力" | ~6 字符 |
| 无信息量套话 | 众所周知/不言而喻 | "众所周知，" | ~4 字符 |
| 无信息量套话 | 希望您不吝… | "希望您不吝赐教" | ~7 字符 |
| 过度修饰 | 极其/非常/超级+形容词 | "极其重要" | ~2 字符 |
| 重复约束 | 同一关键句出现 ≥2 次 | "请务必认真完成"×2 | 整句 |

**防误伤原则**：只报高置信模式；文学/修辞场景（如故意排比）由用户自行判断，引擎不做语义级判断（诚实边界）。

## 4. 压缩规则（compress 意图）

按以下顺序压缩，每步输出"原文→理由→可省量"：

| 优先级 | 规则 | 说明 |
|--------|------|------|
| 1 | 删重复约束 | 同句 ≥2 次整句删除（最高置信） |
| 2 | 删无信息量套话 | 套话对输出质量无贡献 |
| 3 | 删同义堆叠 | 保留一个强化词即可 |
| 4 | 删过度修饰 | 形容词无测量对象（联动 Specificity 维） |
| 5 | 精简指令措辞 | 长句改短句（人工判断，引擎只提示） |

**性能风险预估**：压缩率越高风险越大（借鉴 LLMLingua 权衡思想）——压缩 ≥30% 时标注"高风险区：建议 eval 回归验证不降性能"；RAG/事实任务压缩需保留防幻觉锚点与引用格式。

## 5. 输出规范（Token 报告）

`{估算输入/输出, 预算, 偏差率, 档位, 可删清单[原文→行号→规则→可省量]}`

## 6. 联动

- **Economy 维（Q-Score）**：偏差率 + 冗余命中数作为评分输入（语义维，LLM 判定时用本报告作证据）。
- **P1 评分引擎**：压缩版提示词必须过 score-prompt.mjs 回归（结构不降）。
- **黄金用例**：压缩后性能不降（assets/evals/economy-cases.json 验证）。
