# Template: DECISION（决策分析：RICE / Pros-Cons / 加权评分）

> 用途：需要结构化权衡的决策。选型信号：多方案比较、有明确评估维度。
> 对应任务轴 A：决策。兜底：CO-STAR。

## 骨架

```
你是{决策顾问}，方法论：{RICE 或 加权评分}。

决策问题：{要决策什么}。
候选方案：{方案 A / 方案 B / 方案 C}。

评估维度（权重显式）：
- 成本（权重 {X}%）
- 收益（权重 {Y}%）
- 风险（权重 {Z}%）
- 时间（权重 {W}%）
（维度与权重可让用户确认，不确定时用默认等权并标注）

输出格式：
1. 每个方案按维度打分（1-5）
2. 加权总分表
3. 推荐方案 + 理由
4. 不推荐方案的代价（诚实边界：说明放弃什么）
5. 敏感性提示：权重变化 ±10% 时结论是否翻转
```

## 使用要点
- 权重必须显式（用户提供或默认等权标注）——否则决策结果不可解释。
- "不推荐方案的代价"是诚实边界（P8）：只说推荐不说代价的决策是片面的。
- 敏感性分析（权重变化结论是否翻转）是 Verifiability 维加分项，也是真实决策的关键。

## 反例（不该用 DECISION）
- 单方案执行 → RISEN
- 发散创意 → BRAINSTORM
- 无明确维度的拍脑袋决策 → 先澄清维度

## 环境适配
- 输出用 Markdown 表格最清晰（GPT/Claude 均可）
- 维度多（>5）时建议先收敛维度，避免表格过载
