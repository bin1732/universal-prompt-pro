# references/prompt-cn-practices.md — 中文提示词实践

> 定位：简体中文语境（中文用户、国产模型、中文业务场景）下的提示词编写要点。与 references/environment-matrix.md（模型族方言）、references/techniques.md（技术清单）、references/token-economy.md（用词经济）互补，不重复。

## 语言层要点

1. **中英混排**：专业术语可保留英文（JSON、API、token、prompt），指令主体用中文；避免"中英夹杂"造成指令语义模糊（如"请 summarize 一下"不如"请总结"明确）。
2. **中文标点与全角**：用户输入常含全角标点；指令要求机器解析的格式时明确标点规范（如"输出 JSON，用半角标点"）。
3. **数字与单位**：中文场景常见约束为"200 字 / 3 段 / 5 条"；明确"字"指字符数；英文单词数约束（word limit）对中文任务无效，需换算为字数。

## 中文场景常见失败模式

1. **翻译腔**：欧化长句、被动语态堆叠 → 指令可要求"用中文自然语序，避免翻译腔"。
2. **空泛套话**：高频套话（"充分发挥""众所周知""多措并举"）→ token-economy 已按通用规则检测，写作场景可额外要求"删去无信息量修饰"。
3. **敬语冗余**：客服/商务场景过度敬语（"您务必""敬请"）在输出中易冗余 → 明确语气档位（正式 / 中性 / 亲切），避免堆叠。

## 中文业务场景结构要点

1. **客服话术**：角色（品牌客服）+ 语气档位 + 边界（无法回答时的标准话术）+ 敏感话题转人工。
2. **营销文案**：目标受众 + 卖点排序 + 字数档 + 行动号召；避免夸大承诺（合规要求）。
3. **内容创作**：主题 + 受众 + 篇幅 + 结构要求（开头/主体/结尾）+ 文风（正式/轻松）。
4. **数据分析报告**：数据口径 + 结论先行 + 图表建议 + 数据来源声明。

## 国产模型中文任务适配

1. 中文分段与冒号分节（【】/中文冒号）是国产模型常见方言——构建时按 environment-matrix 方言矩阵选择。
2. 中文任务给出明确输出结构（格式约束）比"自由发挥"更稳定。
3. 中文长度控制（字数/段落数）对国产模型有效；英文单词约束不适用于中文输出。
